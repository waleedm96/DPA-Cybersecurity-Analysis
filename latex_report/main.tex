    \itshape
    How can network traffic analysis help distinguish attacks from normal activity, detect suspicious patterns as traffic arrives, and identify important hosts in network attacks?

\subsection{Data Integration}

% Explain:
% - join keys
% - join type
% - compatibility
% - resulting dataset
The two datasets are joined on the destination port number.
Each flow record carries a \texttt{Dst Port} integer field, which
is matched against the \texttt{Port Number} field in the IANA
registry using an equality join restricted to matching transport
protocols (\texttt{Protocol} $\in\{$TCP, UDP$\}$).
Because the IANA table is only 1.1~MB, Spark can broadcast it
to all executor partitions, eliminating any shuffle. Ports with
no IANA entry are assigned the label \emph{unregistered}, and
flows are further labelled by RFC\,6335 range: \emph{system}
(0--1023), \emph{user} (1024--49151), or \emph{dynamic}
(49152--65535).

\subsection{Why Apache Spark?}
The uncompressed primary dataset is 33.6~GB, which exceeds what
can be loaded into a single machine's memory as a Pandas
dataframe. Spark's partitioned, lazy evaluation model processes
the data in chunks, reading only the columns required for each
query. The columnar Parquet format, combined with Spark's
predicate pushdown, reduces the effective I/O to a small fraction
of the raw CSV volume. Additionally, Spark SQL provides a
declarative interface that separates the analytical logic from
physical execution, making the pipeline reproducible across
different cluster sizes without code changes.

\subsection{Processing Workflow}

% Describe the pipeline in chronological order.

The processing workflow consists of the following main stages:

\begin{enumerate}[leftmargin=1.4em]
    \item Data acquisition and validation;
    \item explicit schema definition and ingestion;
    \item conversion to typed Parquet tables;
    \item data cleaning and validation;
    \item joining of the source datasets;
    \item analytical processing using Spark SQL and/or
          the DataFrame API;
    \item aggregation and generation of the final results.
\end{enumerate}
